# iOS-приложение с демонстрацией дизайн-системы

## О проекте

Это простое тестовое iOS-приложение, демонстрирующее внедрение дизайн-системы, в частности, структурированное хранение и использование цветовых токенов.

Приложение включает в себя:
- Авторизацию через Firebase.
- Ленту новостей, данные которой загружаются по сети.
- Экран настроек, где можно изменять тему оформления и просматривать цветовые токены (эта настройка будет закрыта от пользователя и доступна только в dev режиме).
- Поддержку смены темы оформления с автоматическим применением новых токенов.
- Возможность генерации новых цветовых токенов через скрипт.

## Авторизация

При запуске приложения открывается экран авторизации. Регистрация отсутствует, но её легко можно добавить. В системе уже есть тестовый пользователь с следующими данными:

- **Email:** `user1@gmail.com`
- **Пароль:** `qwerty`

После успешного входа пользователь попадает на **экран ленты новостей**.

## Лента новостей

Данные ленты приходят с сервера (Firebase Firestore). Данные хоть и повторяются, но загружаются по сети, имитируя реальный рабочий процесс. (консоль Firebase starage не очень удобна, что бы быстро создавать много записей)

**Важно!** Клиент закрыт протоколом, а в качестве его боевой имплементации выступает Firebase Firestore. В папку `MockAPIClient` лучше не заглядывать — Firestore не задумывался как удобный инструмент для обработки сложных запросов, поэтому там написан немного "весёлый" код.

## Экран настроек

### В настройках доступны три пункта:
1. **Настройки оформления**
2. **Просмотр токенов** (доступен только в dev-сборке)
3. **Выход из аккаунта** (разлогин пользователя)

### 1. Настройки оформления

Здесь можно выбрать одну из **двух предустановленных тем**:
- bamble
- monochrome  

(состояние сохраняется даже после презагрузки устройства)  
При переключении на **монохромную тему** можно заметить, что цвета приобретают странный розовый оттенок. Это может быть либо ошибка дизайнера, либо скрипт, сгенерировавший токены, отработал неправильно.

### 2. Просмотр токенов

Можно проверить, действительно ли цвета заданы некорректно:
1. Перейти в "Просмотр токенов".
2. Выбрать **monochrome**.
3. Открыть **CommonTheme**.
4. Перейти в **Background**.

Там будет видно, что цветовые токены фона действительно заданы неудачно.

## Обновление цветовых токенов с помощью скрипта

Представим, что дизайнер исправил цвета и прислал обновленный скрипт. Следуем инструкциям:

1. Открываем папку проекта и переходим в `/scripts`.
2. В папке `/CurrentJSON` удаляем старый JSON-файл (или переносим его в другое место).
3. Из папки `/НОВЫЙ_JSON` копируем новый файл и переносим его в `/CurrentJSON`.
4. Открываем терминал и выполняем команду:

   ```sh
   ./scripts/generate_history_theme.swift
   ```

5. После успешного выполнения скрипта токены обновляются.
6. Можно проверить файлы в `/ThemeProvider/CodeGen/` — изменения коснутся только файла, отвечающего за монохромную тему.
7. Запускаем проект, переходим в **Настройки → Оформление** и переключаемся на **Монохромную тему**.

Если всё сделано правильно, новые токены успешно применяются, и цвета становятся корректными.

## Доработки

### 1. Сохранение копии темы в просмотре токенов

Сейчас в просмотре токенов можно создать копию темы, но она не сохраняется в памяти. Необходимо доработать механизм сохранения, чтобы созданные копии можно было использовать в приложении.

### 2. Экспорт темы в JSON и её использование

Самая сложная доработка — возможность **экспортировать пользовательскую тему в JSON и затем использовать её в приложении**. Проблема в том, что экран просмотра токенов не знает ничего о темах (и это правильно). Просто сделать структуры с темами `Codable` нельзя, потребуется делать кастомый инициализтор (`UIColor` не `Codable`). 

Возможные решения:
- **Кастомная инициализация JSON** — но это создаст жёсткую зависимость экрана от структуры тем.
- **Создание универсального метода экспорта** — так, чтобы экран не зависел от внутренней структуры тем.
- **Создние инициализатора с помошью скрипта** - самый понятный и простой способ (уже реализовано объявление структуры, ее дефолтные инициализторы для кадой темы).

Этот момент пока в проработке, но в целом вся система уже готова.
